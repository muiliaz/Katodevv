# AGENTS.md — контекст для AI-агентов

Точка входа для агента, работающего с этим репозиторием. Человеку — сначала
[`frontend/README.md`](frontend/README.md).

Читается за 3 минуты. Если после этого файла остаётся вопрос «а что вообще делает этот проект» —
файл плохой, поправьте его.

---

## Что это за система

Маркетинговый сайт студии разработки **Kato Devv** (https://katodevv.com). Единственная бизнес-цель
— **получить заявку** и доставить её в Telegram-чат команды. Всё остальное — оформление вокруг этой
задачи.

React SPA на четырёх маршрутах + две serverless-функции на Netlify. Ни базы данных, ни аутентификации,
ни личных кабинетов, ни платежей. Единственные внешние зависимости в рантайме — Telegram Bot API.

```
посетитель ─> /web форма ────> /.netlify/functions/contact ─┐
           ─> чат-виджет ────> /.netlify/functions/lead    ─┼─> Telegram-чат
           ─> модалка /bots ─> /.netlify/functions/lead    ─┘
```

Если правка не помогает посетителю дойти до этой стрелки — стоит перепроверить, зачем она.

## Первое, что нужно знать

**`main` автоматически деплоится в продакшен.** Пуш в `main` → сборка Netlify → живой сайт. Нет
staging, нет ручного подтверждения. Ошибка уезжает к посетителям.

**Зелёная сборка ≠ работающий сайт.** Покрытие React-части низкое. Основная ценность `/web` — это
WebGL-сцена и скролл-анимации GSAP, которые `npm run build` собирает молча и которые ломаются
только в браузере. Уже был случай (обновление react-router v7), когда сборка проходила зелёной при
полностью сломанном тестовом раннере.

## Обязательные проверки перед завершением работы

```bash
cd frontend
npm ci && npm run check:env && npm run lint && npm run check:dead && npm run test:coverage && npm run build
```

Это ровно то, что выполняет джоб `build` в CI. Если хоть одна команда красная — работа не закончена.

Шесть шагов: контракт переменных, линтер, поиск мёртвого кода, тесты с порогом покрытия, сборка.
`CI=true` больше не нужна — это было поведение react-scripts.

Рядом идёт второй джоб — **e2e**. Он не входит в цепочку выше: тянет бинарник браузера и рендерит
WebGL программно, поэтому идёт минуты, а не секунды. Запускать локально при правках `/web`,
контактной формы или Turnstile:

```bash
npx playwright install chromium   # один раз
npm run test:e2e
```

## Границы безопасных изменений

### 🟢 Обычная работа

- Тексты и переводы в `frontend/src/shared/lang/` — **кроме** цен и сроков ответа (см. красную зону)
- Стили отдельных компонентов
- Тесты в `frontend/src/__tests__/`
- Логика Netlify Functions — она покрыта тестами на 100% statements, регрессия будет поймана
- Документация

### 🟡 Требует осторожности

| Что | Почему |
|---|---|
| `frontend/src/pages/web/BlackHole/BlackHole.jsx` | WebGL с инлайн-GLSL-шейдерами. Тестами не покрыт, в jsdom не запускается. Проверяется только глазами в браузере |
| `ScrollJourney.jsx`, таймлайны GSAP | Связаны с CSS-классами через строковые селекторы. Переименование класса в CSS тихо ломает анимацию |
| `lang/en.js` и `lang/ru.js` — структура ключей | Читаются многими компонентами; обращение к несуществующему ключу — падение в рантайме, а не ошибка сборки. Два файла обязаны совпадать ключ в ключ, это проверяет `src/__tests__/lang.test.js` |
| `vite.config.mjs` | Держит три неочевидных решения: вывод в `build/` (этого ждёт Netlify), формат имён CSS-модулей и настройку Vitest. Менять — только понимая, что сломается |
| 5 подавлений `react-hooks/exhaustive-deps` | Осознанные, вокруг GSAP/Three.js-таймлайнов. Снятие «на автомате» даёт бесконечные ре-рендеры. Ещё 8 были мёртвыми и убраны |

### 🔴 Не менять без явного решения владельца

| Что | Почему |
|---|---|
| **Цены и срок ответа** | Живут в одном месте — `frontend/src/shared/pricing.js`. Значения выбрал владелец; менять их — его решение, не твоё. Правь только там: `pricing.test.js` уронит сборку, если цена окажется вписана в UI-файл руками |
| Ослабление защиты функций | Honeypot, валидация, лимит частоты и обезличивание ошибок — результат аудита безопасности. Не «упрощать» |
| `public/robots.txt`, `sitemap.xml`, `yandex_*.html` | Обслуживают поисковики и верификацию домена, ссылок из кода нет |
| Домен `katodevv.com` | В пяти местах; `Seo.jsx` берёт его из `shared/site.js`, остальные — литералом. `contracts.test.js` падает, если они разойдутся |

## Решения, которые уже приняты (не переоткрывать без причины)

| Решение | Почему так |
|---|---|
| Заявки идут в Telegram, а не в БД или CRM | Команда маленькая, чат — там, где она и так живёт. Ни хранилища, ни бэкенда не нужно |
| Валидация продублирована на сервере | URL функций публичны: `curl` обходит любые браузерные проверки. `lib/validation.js` — настоящий гейт |
| `parse_mode: 'HTML'`, а не Markdown | У legacy Markdown в Telegram нет документированного экранирования: `*` или `_` в имени ломают сообщение. В HTML достаточно экранировать три символа — см. `lib/telegram.js` |
| Honeypot отвечает «успех» | Бот не должен получить сигнал, что его вычислили, и понять, какое поле его выдало |
| Лимит частоты — в памяти, не в Redis | Ноль зависимостей и конфигурации. Сознательно частичная мера, ограничения расписаны в `lib/rateLimit.js` |
| Тесты функций лежат в `src/__tests__/` | Исторически — Jest от CRA видел только `src/`; после перехода на Vitest перенос возможен, но не обязателен |
| Сборка на Vite, тесты на Vitest | `react-scripts` не сопровождался и давал 16 из 18 предупреждений `npm audit`. После замены осталось 2, и оба неприменимы — см. `audit-fixes/11-vite-migration.md` |
| Portfolio-секция удалена | Была недостижима; её роль выполняет `LaserShowcase` на `/`. Восстанавливается из истории git |

## Типичные ошибки в этом репозитории

1. **Считать зелёный `npm run build` доказательством.** Не является — см. выше.
2. **Удалять «мёртвый» код по имени.** `t.demos.web.navLinks` содержит слово `Portfolio`, но это
   контент макета внутри демо услуг. `portfolioData.js` выглядит осиротевшим, но его читает
   `Bots.js`. Проверять грепом с полными путями.
3. **Чинить `npm audit` через `--force`.** Оставшиеся два предупреждения — про режим RSC в
   react-router, которого здесь нет. Что принято и почему — в `frontend/DEPENDENCIES.md`.
4. **Синхронизировать цены «по большинству».** Красная зона, решает владелец.
5. **Добавлять Prettier или lint «заодно».** Конфига форматирования нет; любой перепишет почти
   каждый файл и утопит содержательный diff.

## Формат сдачи работы

Один логический шаг — один коммит. В сообщении: что было не так, что сделано, почему выбрано это
решение. Комментарии в коде и сообщения коммитов — **по-английски**; документация в `audit-fixes/`
— по-русски. Это сложившийся стиль проекта, а не предпочтение.

Если что-то нельзя доделать своими силами (нужен доступ к панели Netlify, к настройкам GitHub, к
решению по бизнес-значениям) — **не имитировать выполнение**. Написать точную пошаговую инструкцию для
владельца и явно помечать пункт как незакрытый. Примеры такого оформления — в `audit-fixes/04-ci-gate.md`
и `audit-fixes/07-config-hygiene.md`.
