# 01 — Убрать текст внутренней ошибки из ответов

**P0** · аудит vulns, находка Low · 2026-08-05

## Проблема

Обе функции клали текст исключения прямо в тело ответа. Наружу утекало три разных вещи:

| Источник | Что видел посторонний |
|---|---|
| `JSON.parse` | что тело не распарсилось |
| `getCredentials()` | **функция задеплоена без env-переменных** |
| ответ Telegram | `Bad Request: chat not found` — состояние чужого бота |

## Решение и почему так

Один фиксированный текст на все внутренние сбои, детали — в `console.error`.

**Что НЕ прятали:** ответы 400 от валидации. Они описывают ввод самого вызывающего, а не наши
внутренности, и полезны при отладке интеграции.

Перед правкой проверили все три места, где сайт отправляет формы: ни одно не читает поле `error`
(`Contact.js:58` смотрит только `res.ok`, остальные — `json.success`). Значит на интерфейс замена
не влияет.

Константу вынесли в новый `lib/responses.js` — строка part публичного HTTP-контракта двух
эндпоинтов, дублировать её значит гарантировать расхождение.

## Изменено

`lib/responses.js` (создан), `contact.js`, `lead.js`

## Проверка

```
contact 500 -> {"error":"Something went wrong. Please try again later."}
bad JSON    -> то же
validation  -> 400 {"error":"name is too short, email is not a valid address"}
```

Все три источника утечки дают один текст; 400 остался дословным.

## Осталось

Битый JSON отдаёт 500, хотя это ошибка вызывающего. Исправлено на шаге 03.
