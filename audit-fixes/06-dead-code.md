около 2800 строк.

Самое интересное было в границах. Три вещи выглядели мёртвыми, но живые: `portfolioData.js` читает

## Ход рассуждения

### Решение по Portfolio: удалить, а не восстанавливать

Аудит оставляет развилку открытой, поэтому решение принимал мы. Аргументы за удаление:

1. **Замена уже существует и работает.** Аудит сам отмечает в разделе «Подключённые, но
   недоиспользуемые возможности»: «Определить, заменил ли Hub `LaserShowcase` прежнюю секцию
   окончательно». Проверили: `src/pages/hub/LaserShowcase.jsx` живой, смонтирован на `/`, и его
   собственный комментарий описывает его как «CSS-3D coverflow of portfolio cards». То есть
   портфолио на сайте есть — просто в другом месте и в другой форме.
2. **Секция не просто не смонтирована — она была снята намеренно.** `WebDev.js` перечисляет
   компоненты явным списком (`Services`, `About`, `Contact`, `Footer`), и `Portfolio` из него
   исключён. Это не забытый импорт, а сознательное изъятие.
3. **Удаление обратимо.** Всё лежит в истории git; восстановление — один `git revert`.
4. **Цена бездействия реальна.** 755 строк JS + 1780 строк CSS + строки локализации в двух языках,
   которые читаются как живые и вводят в заблуждение и человека, и агента. Это и есть измеряемый
   «когнитивный долг».

Аргумент против — «а вдруг владелец хотел вернуть» — снимается пунктом 3 и тем, что решение
задокументировано здесь и вынесено в `99-summary.md` как открытый вопрос.

### Где именно проходит граница кластера

Это самая ответственная часть шага: удалить слишком много — сломать живые страницы. Поэтому
границу устанавливал грепом, а не на глаз.

**Первая ловушка — `portfolioData.js`.** Аудит прямо предупреждает: «сохранив `PORTFOLIO_DATA.bots.items`,
используемый страницей Bots». Проверили: `src/pages/bots/Bots.js:8` импортирует `PORTFOLIO_DATA`,
`:91` читает `PORTFOLIO_DATA.bots.items`. Файл сохранён.

**Вторая ловушка — `t.demos`.** Первый греп показал, что ветку `demos` используют живые
`Services.js`, `Contact.js`, `About.js`. Значит удалять блок целиком нельзя. Разложили по подветкам:

| Подветка `t.demos` | Потребитель | Решение |
|---|---|---|
| `contact` | `Contact.js:79`, `:157` | ✅ живая, оставлена |
| `about` | `About.js:35`, `:70`, `:71` | ✅ живая, оставлена |
| `web` | `Services.js:12` | ✅ живая, оставлена |
| `mobile` | `Services.js:60` | ✅ живая, оставлена |
| `landing` | только `Portfolio.js:12` | ❌ удалена |
| `business` | только `Portfolio.js:104` | ❌ удалена |
| `ecom` | только `Portfolio.js:243` | ❌ удалена |
| `crm` | только `Portfolio.js:415` | ❌ удалена |

Здесь мы сам чуть не ошибся: промежуточный греп с фильтром по имени файла показал `landing` как
«используемую живым кодом», потому что фильтр применялся к строке, где имя файла уже было отрезано.
Перепроверка с полными путями показала, что все четыре ветки принадлежат только `Portfolio.js`.
Записываем это, потому что ошибка была бы тихой: удалили бы живую ветку — упал бы рендер `Services`.

**Третья ловушка — `navLinks`.** В `LangContext` есть строка
`navLinks: ["About", "Services", "Portfolio", "Contact"]`, и слово «Portfolio» в ней провоцирует
удалить. Проверили: это `t.demos.web.navLinks`, который читает `Services.js:23` — **содержимое
макета фальшивого сайта** внутри демонстрации услуг, а не навигация настоящего сайта. Не тронуто.

| `t.demos.{landing,business,ecom,crm}` (EN + RU) | см. таблицу выше |

### Как выполнял удаление в `LangContext.js`

Файл на 865 строк, блоки продублированы для `en` и `ru`. Удалять руками по номерам строк — верный
способ съехать на строку и получить синтаксически валидный, но семантически сломанный объект.

Поэтому: скрипт, который для каждого начала блока находит закрывающую строку **с тем же отступом**,
и удаление диапазонов **с конца файла к началу** (иначе первое же удаление сдвигает все последующие
номера). Границы напечатал и проверили глазами перед удалением:

```
строка 234: portfolio: {  -> конец 250: },
строка 336: landing: {    -> конец 364: },
строка 365: business: {   -> конец 406: },
...
```

После удаления — проверка синтаксиса парсером, а не «на глаз»:

```
$ node -e "require('@babel/parser').parse(...)"
✓ синтаксис LangContext.js валиден
```

### Остаточные селекторы в `ScrollJourney`

Аудит отмечает отдельно: «`ScrollJourney` ищет отсутствующие элементы `.portfolio`, безопасно не
выполняя полезной работы» (критерий «Функционально нерелевантный код», 3/5).

Убрали два места: `.portfolio h2` из общего селектора заголовков и весь блок анимации
`.portfolio-card` / `.portfolio-grid`. Заодно поправили док-комментарий в шапке файла, который
описывал `portfolio/other` как анимируемую секцию — иначе комментарий пережил бы код, который
описывает.

### `CATEGORY_KEYS` — то, что стало мёртвым в результате

`portfolioData.js` экспортировал `CATEGORY_KEYS`, который читал только `Portfolio.js`. После
удаления экспорт осиротел — убран.

**А вот сами данные категорий `web`, `mobile`, `automation` внутри `PORTFOLIO_DATA` оставлены**,
хотя `Bots.js` читает только `.bots.items`. Причина: критерий завершения в аудите сформулирован
как «`Portfolio.js`, CSS, его локализация и остаточные селекторы удалены; Bots продолжает
использовать свои данные» — обрезка данных в него не входит. Расширять удаление за границу,
поставленную аудитом, без нужды не стали. Зафиксировано ниже как остаток.

### `web-vitals` — единственная находка с неполной уверенностью

Аудит даёт 82% и класс `likely_unused`, а не `confirmed`, и просит проверить перед удалением.
Проверили:

```
$ grep -rn "web-vitals\|reportWebVitals" src/ public/
(пусто)
```

Ни импорта, ни вызова, ни файла `reportWebVitals.js`, который CRA генерирует по умолчанию, — его
удалили раньше, а зависимость осталась. Удалено через `npm uninstall`.

### `favicon-kd.svg` — намеренно не тронут

Аудит помечает его `weak_signal` и предупреждает: «публичный ресурс может иметь прямой внешний URL…
до этого не удалять автоматически». Согласен и не трогаем — вынесено в открытые вопросы.
