# 07 — Гигиена конфигурации

**P2** · аудиты config-hygiene (53/100), tech-health TH-002, cicd (шаг 6) · 2026-08-05

## Проблема

Обязательные `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID` можно было узнать только из кода. Дефект хуже,
чем кажется: без них сайт **выглядит рабочим** — собирается, форма рисуется, кнопка нажимается, —
а заявка молча теряется с ответом 500. Ни сборка, ни CI такого не ловят.

После шага 01 стало ещё строже: наружу идёт обезличенный текст, и диагностика полностью переехала в
логи Netlify.

## Решение

`.env.example` с именами ключей, без значений, и с указанием **где** их задавать (панель Netlify,
scope Functions) — аудит требовал именно этого: «новый сопровождающий называет оба ключа, не
открывая telegram.js».

Шаблон без проверки устареет на первой же новой переменной, поэтому добавили `check:env` в CI:
скрипт сканирует `netlify/functions/**` и падает с именем переменной, которой нет в шаблоне.

Проверили, что `.env.example` не попадёт под `.gitignore` — паттерн `*.env` матчит окончание, а не
начало. Молча проигнорированный шаблон был бы худшим исходом шага.

## Закрепление CI

`ubuntu-latest` → `ubuntu-24.04`, добавлен `permissions: contents: read`.

Actions сначала оставили на плавающих тегах с формулировкой «нет доступа к сети». **Это было
неверно** — проверили только отсутствие `gh`. Дозакрыто 2026-08-06: оба тега `v4` разыменованы через
API и закреплены на коммиты. Обновлять до v7 не стали — аудит просил закрепить, а не обновить, и v4
уже отработала зелёной.

## Проверка

Мутацией убедились, что ловит: добавили `process.env.TELEGRAM_API_BASE` в `telegram.js` →


`job id` остался `build` — имя обязательной проверки не изменилось.
