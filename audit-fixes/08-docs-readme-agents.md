## Проблема

`frontend/README.md` был шаблоном Create React App. Продуктового контекста в отслеживаемых файлах не
было вовсе.

## Поправка к аудитам

Контекст в репозитории **был**, просто не закоммичен: в корне лежит `PROJECT.md` на 26 КБ,
исключённый строкой `.gitignore:43` как «Internal docs». Задача свелась не к сочинению с нуля, а к
извлечению и актуализации — он местами устарел (описывает `/backend` на Express, удалённый в
`b99ed74`).

Сам `PROJECT.md` не трогали и не разгитигнорили: владелец пометил его внутренним, это его решение.

## Два файла, а не один

`frontend/README.md` — человеку: как запустить, как устроено, как деплоится.
`AGENTS.md` в корне — агенту: что можно трогать, что нельзя, чем проверять.

Аудиты просят разного, и один файл либо раздулся бы, либо потерял половину.

## Что необычного внутри

**README перечисляет, чего тестов нет.** Документ, где только достижения, создаёт ложное ощущение
покрытия — ровно та ошибка, за которую аудит тестов снимал баллы.

**AGENTS.md содержит «Типичные ошибки в этом репозитории»** — не абстрактные советы, а грабли, на
которые мы наступили: зелёная сборка при сломанном раннере, `navLinks` со словом «Portfolio»,
`npm audit fix --force`, предлагающий снести сборщик.

**Полноценные ADR писать не стали** — история неглубокая, сочинять причины задним числом хуже, чем
не писать. Вместо этого таблица решений, каждое из которых проверяемо по коду. ADR появились на
шаге 15, когда стало ясно, что именно восстанавливается достоверно.

## Проверка

Все внутренние ссылки проверены скриптом — битых нет. Каждая команда из документов реально
выполнялась в этой сессии.

README писали предпоследним намеренно: иначе к концу работы он врал бы про `web-vitals`, Portfolio и
версии.

## Осталось

Судьба `PROJECT.md` — решение владельца. Постоянный handoff-формат не заведён; эту роль пока
