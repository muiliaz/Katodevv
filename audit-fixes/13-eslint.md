# 13 — Возврат линтера

**Приоритет:** P2
**Аудит-источники:** `…audit-tech-health…md` (TH-005), `…audit-cicd…md` (шаг 5)
**Дата:** 2026-08-07

## В двух словах

Неприятный побочный эффект нашей же миграции: вместе с `react-scripts` ушёл встроенный ESLint, и
проект какое-то время жил **вообще без линтера** — то есть по этому пункту стал хуже, чем был до
начала работы по аудитам.

Вернули. Только линтер, без форматтера — и он сразу нашёл две находки, которые аудиты отмечали
по отдельности.

---

## Проблема

TH-005:

> **Форматирование и lint-процесс не закреплены явно.** В `frontend/package.json:24-35` нет
> `lint`/`format`; отдельные конфиги форматирования отсутствуют; найдено 13 подавлений
> `react-hooks/exhaustive-deps`.

Аудит CI/CD, шаг 5: «Решить, нужны ли отдельные lint и typecheck проверки».

Раньше линтер был неявным — `react-scripts` гонял его на каждой сборке. После шага 11 не осталось
ничего.

## Ход рассуждения

### Почему без Prettier

TH-005 просит и форматирование. Отказались сознательно: Prettier перепишет почти каждый файл, и
содержательные изменения утонут в диффе пробелов. Это отдельное решение и отдельный коммит.

### Почему не «recommended» набор правил

Плагин `eslint-plugin-react-hooks` v6 в наборе `recommended` тянет правила React Compiler:
`immutability`, `preserve-manual-memoization`, `set-state-in-effect`. На первом прогоне они дали
**15 ошибок** — но ни одна не была багом. Они сообщают, что код нельзя автоматически оптимизировать.

Принять их — значит переписывать компоненты вокруг GSAP и Three.js. Это проект по оптимизации, а не
список дефектов. Оставили два классических правила, которые и применял CRA:
`rules-of-hooks` (ошибка) и `exhaustive-deps` (предупреждение).

### Что линтер нашёл сразу

**TH-006 — тихие `catch`.** Аудит просил: «сохранить безопасный fallback, но добавить ограниченную
dev-диагностику или комментарий о причине ожидаемого подавления».

| Где | Почему молчит |
|---|---|
| `ChatWidget.jsx:40` | `sessionStorage` падает в приватном режиме и при переполнении квоты, а сохранённое значение может быть устаревшим JSON. Посетитель ничего из этого сделать не может; пустой диалог — правильный исход во всех случаях |
| `BlackHole.jsx:499` | Выполняется **каждый кадр**. Эффект виньетки может быть не готов, а `postprocessing` менял местоположение свойства между версиями. Логирование засорило бы консоль 60 раз в секунду ради косметики |

Оба теперь несут объяснение прямо в коде — TH-006 закрыт.

**TH-005 — подавления.** Из 13 подавлений `exhaustive-deps` **восемь больше ничего не подавляют**:
правило на них не срабатывает. Убраны `--fix`. Остальные оставлены видимыми как предупреждения.

## Как проверено

```
$ npm run lint
(пусто — 0 ошибок, 0 предупреждений)
```

**Проверка, что правила живые** — временный компонент с двумя намеренными нарушениями:

```
5:17  error  React Hook "useState" is called conditionally…   react-hooks/rules-of-hooks
8:9   error  'unusedVar' is assigned a value but never used   no-unused-vars
✖ 2 problems
```

Полный прогон после всех правок: **88 тестов**, сборка зелёная.

Шаг `Lint` добавлен в CI **до** тестов — он выполняется за секунды, и незачем ждать полного набора,
чтобы узнать о неиспользуемой переменной.
