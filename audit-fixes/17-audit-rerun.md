## Гигиена зависимостей: 2 предупреждения → **0**

```
$ npm audit
found 0 vulnerabilities
$ npm audit --omit=dev
found 0 vulnerabilities
```

**Мы для этого ничего не делали, и это главное в находке.** `react-router-dom` как был, так и
остался `7.18.2` — изменилось само предупреждение. GHSA-qwww-vcr4-c8h2 обновлено **2026-08-07 в
18:16 UTC**, и уязвимый диапазон на ветке 7.x сузился:

| | Было (когда писали EXC-002) | Стало |
|---|---|---|
| Диапазон 7.x | `>=7.12.0 <8.3.0` | `>=7.12.0 <7.18.2` |
| Первая исправленная | — (на 7.x не существует) | **7.18.2** |

То есть версия, которая у нас стоит, и есть исправленная. `EXC-002` закрыт, `DEPENDENCIES.md`
обновлён.

Отдельно стоит отметить, **как** запись EXC-002 состарилась. В ней написано: «исправленной версии на
ветке 7.x не существует, а ветки 8.x на момент записи ещё нет». На момент записи это было правдой и
подтверждалось выводом `npm view`. Через несколько часов стало неправдой. Реестр принятых
предупреждений — живой документ не для красоты: запись без перепроверки живёт примерно один день.

### Что нашлось попутно

**Цифра «lockfile 1383 → 229» в `DEPENDENCIES.md` устарела почти вдвое.** Она была верна ровно на
коммите миграции и с тех пор росла вместе с инструментами:

| Коммит | Записей в lockfile | Что добавилось |
|---|---:|---|
| `dc5dea2` (до работ) | 1384 | — |
| `de61d7a` | **229** | замена react-scripts на Vite |
| `c672f06` | 325 | ESLint |
| `4f851a3` | 383 | knip, покрытие |
| `fe4c465` | **387** | Playwright |

Это не регрессия: весь прирост — dev-инструменты, в runtime-установку они не попадают
(`npm audit --omit=dev` видит 82 prod-пакета из 386). Но заголовочное число в документе занижало
дерево на 69%, и его надо было поправить.

**Пять пакетов отстают от latest.** Ни один не создаёт предупреждения; два интересны:

| Пакет | Стоит | Latest |
|---|---|---|
| `@testing-library/user-event` | 13.5.0 | 14.6.3 |
| `@testing-library/jest-dom` | 6.9.1 | 7.0.1 |
| `three` | 0.183.2 | 0.185.1 |
| `@react-three/postprocessing` | 3.0.4 | 3.0.5 |
| `eslint` | 10.8.0 | 10.8.1 |

`user-event` v13 — мажор из другой эпохи: в v14 API стал асинхронным (`await user.click()` и
`userEvent.setup()`). Обновление механическое, но затрагивает каждый тест, который что-то нажимает.
Это отдельная задача, а не строчка в `npm update`.

**Оценка:** исходные 33/100 → предупреждений ноль, цепочка сборки закреплена, реестр исключений
пуст. Единственное живое замечание — отставание `user-event` на мажор.

## Мёртвый код: knip чист, но **153 CSS-класса ничем не используются**

```
$ npx knip --include files,dependencies,unlisted,unresolved,exports,nsExports,duplicates,binaries
(пусто)
```

По JavaScript претензий нет: ни недостижимых модулей, ни лишних зависимостей, ни неиспользуемых
экспортов — в том числе после того, как шаг 16 добавил семь новых файлов.

**И здесь же граница инструмента: knip не читает CSS.** Проверка «класс объявлен в `.css`, но его
имя не встречается ни в одном `.js`/`.jsx`»:

| Файл | Мёртвых / всего |
|---|---|
| `pages/web/Hero.css` | **68 / 94** |
| `pages/web/Services.css` | 52 / 201 |
| `pages/web/About.css` | 27 / 55 |
| `app/App.css` | 3 / 7 |
| `pages/hub/Hub.css` | 3 / 58 |

Проверено руками, а не только счётчиком:

- `Hero.css` — целые кластеры `.holo-*` (17 классов: `holo-flip-wrapper`, `holo-beam`, `holo-scan-line`…)
  и `.sb-*` (`sb-telegram`, `sb-nn-node`…). Это остатки варианта героя, которого в коде больше нет.
- `About.css` — блок `.abt-seniors`, `.abt-senior-card`, `.abt-crown-badge`, `.abt-staff-*`.
  `About.jsx` использует 20 классов `abt-*` из 55.
- `App.css` — `.lang-switcher`, `.lang-divider`, `.w3`.

⚠️ **Три класса в `Hub.css` — `hub-card-bots`, `hub-card-web`, `hub-card-apps` — в этот список
попали, но удалять их вслепую нельзя:** имена такой формы обычно собираются шаблоном. В `Hub.jsx`
такого шаблона нет (там `data-card-key`), но проверять надо в браузере, а не грепом. Ровно та
ошибка, от которой предостерегает `docs/handoff.md` в пункте про «Portfolio».

Это находка, а не выполненная работа: удаление 153 правил — отдельная задача с проверкой глазами на
всех четырёх маршрутах. Записана в handoff.

**Оценка:** исходные 68/100 → по JS всё закрыто и автоматизировано, но обнаружен целый класс
мёртвого кода, которого исходный аудит не касался и который автопроверка не видит.

### Что цифра покрытия не говорит

**44,46% занижают реальность.** `WebDev.jsx`, `BlackHole.jsx`, `ScrollJourney.jsx` показывают 0% —
и при этом каждый прогон e2e грузит их в настоящем браузере. Покрытие считает только запуск Vitest;
e2e идёт по собранному бандлу и не инструментирован. Сводить их в одно число мы не стали: это
потребовало бы отдельной сборки с инструментацией, а полученное число всё равно смешивало бы две
разные проверки.

**Что действительно не покрыто ничем:**
