# Аудит CI/CD репозитория anastasiakrivova-stack/-

## Краткое резюме

- Текущий CI/CD имеет полезную основу, но пока не защищает ветку `main` и путь поставки от непроверенных изменений: проверки настроены, однако не обязательны, а их успешная работа не подтверждена ни одним наблюдаемым запуском.
- Конвейер — автоматический путь проверки изменений — валиден и выполняет `npm ci`, `npm run test:ci` и `npm run build` для запросов на слияние и отправки изменений в `main`.
- Главный риск: gate, то есть проверка, способная остановить плохое изменение, отсутствует на уровне ветки. `main` не защищена, обязательных проверок статуса и наборов правил нет.
- Уверенность средняя: файлы и настройки ветки подтверждены напрямую, но история GitHub Actions пуста, а связанный сайт Netlify не указан.
- Лучший следующий шаг — подтвердить первый зелёный запуск `CI / build`, затем сделать эту проверку обязательной для `main`.

## Цель аудита

- Репозиторий: [`anastasiakrivova-stack/-`](https://github.com/anastasiakrivova-stack/-)
- Аудированная ветка: [`main`](https://github.com/anastasiakrivova-stack/-/tree/main)
- Полный коммит: [`dc5dea254168fb8d6d6f2e9d956bec14b26066da`](https://github.com/anastasiakrivova-stack/-/commit/dc5dea254168fb8d6d6f2e9d956bec14b26066da)
- История получена с глубиной 1; это достаточно для текущей статической проверки, но не для выводов о долгосрочной стабильности.

## Что было проверено

Проверены конфигурация GitHub Actions `.github/workflows/ci.yml`, команды в `frontend/package.json`, lockfile, декларация поставки `netlify.toml`, состояние защиты `main`, rulesets, окружения и доступная история запусков. Конфигурация сопоставлена с двумя поставляемыми частями: статическим React-приложением и Netlify Functions.

Файл проектных указаний `GUARD.md` или `ENJI_GUARD.md` отсутствует. Поэтому дополнительные проектные ограничения не меняли область проверки, находки, уверенность или оценку. Контейнеризация признана неприменимой: Dockerfile, compose-файлы, реестр образов и container deployment в репозитории отсутствуют.

## Результаты

### Основной ответ
> [!WARNING]
> **Вопрос аудита:** Насколько хорошо текущий процесс CI/CD защищает ветку по умолчанию и путь поставки от непроверенных изменений, и какая последовательность следующих шагов сделает его надёжным?
>
> **Ответ:** Защита пока недостаточна, с оценкой 58/100 и средней уверенностью: валидный CI запускает содержательные проверки, но `main` не требует их прохождения, а зелёный запуск ещё не наблюдался. Сначала следует подтвердить `CI / build`, затем сделать его обязательным для `main`, после чего закрепить версии runner и actions.

### Расчет оценки

Оценку подняли валидная конфигурация, реальные тесты и сборка, совпадение локальных и CI-команд и декларативная поставка в Netlify. Главным снижением стало отсутствие обязательного gate для `main`; дополнительно повлияли пустая история запусков и плавающие ссылки на окружение CI.

Сумма оценённых критериев: 37 из 55, то есть `round(37 / 55 × 100) = 67`; затем вычтено 8 баллов за отсутствие обязательных проверок и 1 балл за плавающие ссылки, итого `67 − 8 − 1 = 58/100`. Ограничение 59 для необязательного gate не изменило результат, потому что 58 уже ниже него.

| Окружение CI может меняться без изменения репозитория | Низкое: ухудшается воспроизводимость сбоев | Высокая | `ubuntu-latest`, `actions/checkout@v4`, `actions/setup-node@v4` | После настройки gate закрепить runner и actions на управляемые версии или SHA |

## Доказательства

- `.github/workflows/ci.yml` прошёл `actionlint` без замечаний и содержит три содержательных шага: `npm ci`, `npm run test:ci`, `npm run build`.
- `frontend/package.json`, `frontend/package-lock.json` и `netlify.toml` синтаксически валидны; требуемые команды и lockfile существуют.
- Метаданные `main` показывают `protected=false`, отключённые required status checks и пустой список contexts; список rulesets также пуст.
- В доступной истории GitHub Actions нет зарегистрированных workflow и запусков, хотя `.github/workflows/ci.yml` присутствует в аудированном коммите.
- `netlify.toml` задаёт `base=frontend`, `command=npm run build`, `publish=build` и `functions=netlify/functions`.

## Ограничения

- История Git получена с глубиной 1, поэтому долгосрочные тенденции и прежняя стабильность конвейера не оценивались.
- Выделенный endpoint защиты ветки был недоступен, но отсутствие защиты независимо подтверждено метаданными `main` и пустым списком rulesets.
- Пустая история запусков не доказывает ошибку конфигурации, но не позволяет подтвердить фактическое здоровье CI или длительность обратной связи.
- Связанный сайт Netlify не указан, поэтому состояние развертываний, внешние approvals и возможность отката не наблюдаемы.
- Контейнеризация отсутствует и признана неприменимой, а не недостатком.
- Предыдущий сопоставимый аудит CI/CD недоступен; этот результат становится исходной точкой для следующего сравнения.
