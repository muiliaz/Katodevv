**Было затронуто:** 16 записей — `@svgr/*`, `css-select`, `nth-check`, `postcss`, `svgo`,

Подробности решения и проверки — в `audit-fixes/11-vite-migration.md`.

приходили только через `react-scripts`. Они удалены из `package.json`.

## EXC-002 — `react-router` GHSA-qwww-vcr4-c8h2 (RSC Mode CSRF Bypass)

**Затронуто (2 записи):** `react-router@7.18.2`, `react-router-dom@7.18.2`
**Ссылка:** https://github.com/advisories/GHSA-qwww-vcr4-c8h2
**Уязвимый диапазон:** `>=7.12.0 <8.3.0`

**Статус:** принято — неприменимо к этому проекту
**Владелец:** владелец репозитория
**Пересмотреть:** когда выйдет `react-router-dom` 8.3.0 или новее

### Почему не исправлено

Исправленной версии на ветке 7.x не существует, а ветки 8.x на момент записи ещё нет:

```
$ npm view react-router-dom dist-tags
{ "latest": "7.18.2", ... }     # 8.x не опубликована
```

Единственное, что предлагает npm, — откат на `7.11.0`. Это означало бы уйти на более старый выпуск
ради предупреждения, которое к проекту не относится.

### Почему это неприменимо

Предупреждение касается **режима RSC** (React Server Components) и обхода CSRF-защиты при выполнении
server actions. Этот проект — клиентский SPA:

- `frontend/src/app/App.jsx` использует `BrowserRouter`, `Routes`, `Route`;
- страницы используют `Link` и `useNavigate`;
- RSC, data routers, `action`/`loader` и серверный рендеринг не используются нигде.

Уязвимый код в бандл не попадает и исполняться не может.

### История

Исходный аудит гигиены зависимостей рекомендовал обновление `react-router-dom` 6.30.4 → 7.18.2, и
оно выполнено (шаг 05). Оно закрыло предупреждение, из-за которого рекомендация и возникла. Данное
предупреждение — **новое**, появившееся уже на рекомендованной версии. Это нормальная динамика, а не
ошибка обновления.

### План устранения

Обновиться до `react-router-dom` 8.3.0 или новее, когда она выйдет. Поверхность использования узкая
(пять API), поэтому обновление ожидается недорогим. Проверяется тестами в
`frontend/src/__tests__/routing.test.jsx`.
