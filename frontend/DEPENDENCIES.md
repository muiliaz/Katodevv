# Реестр принятых предупреждений по зависимостям

Живой документ. Здесь фиксируются предупреждения `npm audit`, которые **осознанно оставлены
неисправленными**, с причиной, владельцем и датой пересмотра.

Смысл файла: без него нельзя отличить обдуманный технический долг от незамеченного дрейфа. Если
предупреждение не описано здесь — значит оно новое и требует разбора, а не молчаливого игнорирования.

**Последнее обновление:** 2026-08-05
**Состояние `npm audit` на эту дату:** 18 предупреждений (13 high, 5 moderate, 0 critical, 0 low)

---

## Как пользоваться

```bash
cd frontend
npm audit                # текущее состояние
npm audit --omit=dev     # то, что реально попадает в runtime-установку
```

Если появилось предупреждение, которого нет в таблицах ниже — его нужно либо исправить, либо
добавить сюда с обоснованием. Пустая строка «принято» без причины не считается обоснованием.

## EXC-001 — Цепочка сборки `react-scripts@5.0.1`

**Затронуто (16 записей):** `@svgr/plugin-svgo`, `@svgr/webpack`, `css-minimizer-webpack-plugin`,
`css-select`, `nth-check`, `postcss`, `react-scripts`, `resolve-url-loader`, `rollup-plugin-terser`,
`serialize-javascript`, `sockjs`, `svgo`, `uuid`, `webpack-dev-server`, `workbox-build`,
`workbox-webpack-plugin`

**Статус:** принято временно
**Владелец:** владелец репозитория
**Пересмотреть:** при переходе на другой сборщик, но не позже 2027-02-01

### Почему не исправлено

Исправленной версии не существует. `npm audit` для каждой из этих записей предлагает
`fixAvailable: {"name":"react-scripts","version":"0.0.0"}` — то есть «понизить `react-scripts` до
несуществующей версии 0.0.0», что на практике означает «удалить сборщик». Проект
`create-react-app` не сопровождается, и выпуска с исправлениями не будет.

### Почему это приемлемо прямо сейчас

Все перечисленные пакеты — **инструменты сборки и dev-сервера**. Продукт представляет собой
статический сайт: в `build/` попадают HTML, CSS и JS-бандлы. Ни один из этих пакетов не исполняется
в браузере посетителя и не исполняется на Netlify в рантайме.

Реальные векторы для них — «атакующий имеет сетевой доступ к вашему dev-серверу» или «вы собираете
недоверенный исходный код». Ни то, ни другое к этому проекту не относится: dev-сервер поднимается
локально, исходники свои.

Косвенное подтверждение: аудит безопасности (`auditfiles/…-audit-vulns-…md`), который специально
искал эксплуатируемые риски, поставил **92/100** и не упомянул `react-scripts` вообще. Аудит
гигиены зависимостей, поставивший 33/100, сам оговаривается: «Приоритеты здесь отражают срочность
для гигиены зависимостей, а не утверждают возможность эксплуатации».

### План устранения

Замена сборщика (Vite или аналог). Объём, риски и порядок описаны в
`audit-fixes/05-dependency-hygiene.md`, раздел «План миграции». Это отдельный проект с обязательной
визуальной проверкой `/web`, а не пункт в списке обновлений.

### Чего делать НЕ надо

Не запускать `npm audit fix --force`. На этих записях он снесёт `react-scripts` и оставит проект
без сборки и без тестов.

## EXC-002 — `react-router` GHSA-qwww-vcr4-c8h2 (RSC Mode CSRF Bypass)

**Затронуто (2 записи):** `react-router@7.18.2`, `react-router-dom@7.18.2`
**Ссылка:** https://github.com/advisories/GHSA-qwww-vcr4-c8h2
**Уязвимый диапазон:** `>=7.12.0 <8.3.0`

**Статус:** принято — неприменимо к этому проекту
**Владелец:** владелец репозитория
**Пересмотреть:** когда выйдет `react-router-dom` 8.3.0 или новее

### Почему не исправлено

Исправленной версии на ветке 7.x не существует, а ветки 8.x на момент записи ещё нет:

```
$ npm view react-router-dom dist-tags
{ "latest": "7.18.2", ... }     # 8.x не опубликована
```

Единственное, что предлагает npm, — откат на `7.11.0`. Это означало бы уйти на более старый выпуск
ради предупреждения, которое к проекту не относится.

### Почему это неприменимо

Предупреждение касается **режима RSC** (React Server Components) и обхода CSRF-защиты при выполнении
server actions. Этот проект — клиентский SPA:

- `frontend/src/app/App.js` использует `BrowserRouter`, `Routes`, `Route`;
- страницы используют `Link` и `useNavigate`;
- RSC, data routers, `action`/`loader` и серверный рендеринг не используются нигде.

Уязвимый код в бандл не попадает и исполняться не может.

### История

Исходный аудит гигиены зависимостей рекомендовал обновление `react-router-dom` 6.30.4 → 7.18.2, и
оно выполнено (шаг 05). Оно закрыло предупреждение, из-за которого рекомендация и возникла. Данное
предупреждение — **новое**, появившееся уже на рекомендованной версии. Это нормальная динамика, а не
ошибка обновления.

### План устранения

Обновиться до `react-router-dom` 8.3.0 или новее, когда она выйдет. Поверхность использования узкая
(пять API), поэтому обновление ожидается недорогим. Проверяется тестами в
`frontend/src/__tests__/routing.test.js`.

## Про `bfj` — отдельно

Запись `bfj` из ранних прогонов `npm audit` больше не показывается после `npm audit fix`, но если
она вернётся: `react-scripts/scripts/build.js:28` подключает `bfj` безусловно, а **использует**
только при запуске с флагом `--stats` (строка 55: `const writeStatsJson = argv.indexOf('--stats') !== -1`).
Ни CI, ни Netlify этот флаг не передают, поэтому уязвимый код недостижим.

Переопределять `bfj` на 9.x не следует: это мажорный скачок пакета, который подключается через
`require()` на верхнем уровне скрипта сборки. Если формат экспорта изменился, сборка перестанет
запускаться целиком — ради недостижимого кода.
